# Form components

The form system is in `app/src/components/form/`. `useAppForm` (`app/src/hooks/form.ts`) registers its fields and its submit button, so a form renders `field.TextField` inside `form.AppField` and `form.SubmitButton` inside `form.AppForm`, and never imports a field. How to build a form (schemas, create and edit modes, validation, submit) is in [forms](../03-patterns/forms.md), which also has the table of each field's value type and props. This page lists what exists and which control each field wraps.

## Fields

Each field is a file of `app/src/components/form/fields/`, registered in `fieldComponents` of `app/src/hooks/form.ts`.

| Field | File | Wraps |
| --- | --- | --- |
| `field.TextField` | `text-field.tsx` | `Input` |
| `field.TextAreaField` | `textarea-field.tsx` | `Textarea`. The component is named `TextareaField` in its file and registered as `TextAreaField`. |
| `field.NumberField` | `number-field.tsx` | `NumberInput` |
| `field.MoneyField` | `money-field.tsx` | `Input`, with the currency beside it; the value is the string typed in major units |
| `field.SelectField` | `select-field.tsx` | `Select` |
| `field.ComboboxField` | `combobox-field.tsx` | `Combobox` |
| `field.CheckboxField` | `checkbox-field.tsx` | `Checkbox` |
| `field.DateTimeField` | `date-time-field.tsx` | `DateTimePicker`; the value is the text a `datetime-local` input holds (`2027-03-03T10:00`, no zone, empty when nothing is chosen), so a form says which zone it is read in and converts it itself; the picker shows the same moment on the clock of the browser when that is not UTC. The label names the pair of controls as a group, and the date button too: a test finds the button by its role and name (`getByRole('button', { name })`), not by `getByLabel`, which finds both |
| `field.DatePickerField` | `date-picker-field.tsx` | `DatePicker` |
| `field.DateRangePickerField` | `date-range-picker-field.tsx` | `DateRangePicker` |
| `field.JsonField` | `json-field.tsx` | A CodeMirror editor that lints JSON |

Every field takes `label` and, optionally, `description`, `required` and `className`. The controls they wrap are in [UI components](./ui-components.md#inputs) and [Pickers](#pickers).

The story `Components/Form/Fields` ([`form-fields.stories.tsx`](../../src/components/form/fields/stories/form-fields.stories.tsx)) renders the fields, except `JsonField` and `DateRangePickerField`.

## Building blocks

The fields are composed from a few blocks, which a screen can also use to build a field of its own.

| Block | File | Role |
| --- | --- | --- |
| `FormField` | `fields/form-field.tsx` | The frame of a field: label, `RequiredMark`, description, error message. It takes a render function that receives the `field` from `useField`. |
| `useField` | `fields/use-field.ts` | Reads the TanStack Form field context: `value`, `errors`, `handleChange`, `handleBlur`, `hasError` (the field is touched and has an error) and `errorMessage`, already passed through `t`. |
| `FormItem`, `FormLabel`, `FormControl`, `FormDescription`, `FormMessage` | `form-item.tsx`, `form-label.tsx`, `form-control.tsx`, `form-description.tsx`, `form-message.tsx` | The parts `FormField` renders. They share ids through a context, so the label, the description and the message are linked to the control by `aria-describedby`, `aria-invalid` and `aria-required`. `FormControl` takes `announceRequired={false}` for a control that renders a button or a bare container, which ARIA does not let carry `aria-required` (the date pickers, the CEL rule preview, the JSON editor, the checkbox row). |
| `RequiredMark` | `required-mark.tsx` | The asterisk drawn beside a required label, outside the `<label>` so the label text stays the field's name. |
| `SubmitButton` | `submit-button.tsx` | Registered as `form.SubmitButton`. It takes `label` and `allowPristine`; see [forms](../03-patterns/forms.md). |
| `FormStateBridge` | `form-state-bridge.tsx` | Reports `canSubmit`, `isSubmitting`, `isPristine` and `isValidating` to a parent callback. It sits inside a `form.Subscribe`, as in `app/src/features/feature-flags/targeting/components/basic-targeting-form.tsx`. |
| `form-context.tsx` | `form-context.tsx` | `fieldContext`, `formContext`, `useFieldContext` and `useFormContext`, the contexts `createFormHook` needs, and the item context the blocks share. |

A field that only one feature needs stays in that feature and is composed from these blocks. `CelField` (`app/src/features/feature-flags/targeting/components/cel-field.tsx`) reads `useFieldContext` and renders `FormItem`, `FormLabel`, `FormControl`, `FormDescription` and `FormMessage` around a CEL editor.

## Pickers

Six inputs sit at the top of `app/src/components/`, outside `ui/`: they compose several primitives. `Combobox`, `DatePicker`, `DateRangePicker` and `DateTimePicker` have a form field of their own (`ComboboxField`, `DatePickerField`, `DateRangePickerField`, `DateTimeField`). `TimeField` is the time half of `DateTimePicker`, and is used on its own where only a time of day is needed.

There is no native date or time input in the console: `type="date"`, `type="time"` and `type="datetime-local"` give each browser its own popup, language, 12 or 24-hour clock and keyboard, and nothing a test can drive the same way twice. A UTC day is picked with `DateInputPicker`, a UTC date and time with `DateTimePicker`, and a time of day with `TimeField`. The local-time `DatePicker` is for a moment the person thinks of in their own zone.

| Component | What it is | Story |
| --- | --- | --- |
| `Combobox` (`combobox.tsx`) | A searchable single choice on `Popover` and `ComboboxPanel`. `allowCustomValue` lets the user commit a typed value, `clearable` adds a clear action. | [combobox](../../src/components/stories/combobox.stories.tsx) |
| `DatePicker` (`date-picker.tsx`) | A date chosen from a `Calendar` in a popover. | [date-picker](../../src/components/stories/date-picker.stories.tsx) |
| `DateRangePicker` (`date-range-picker.tsx`) | A range of dates from a `Calendar`. | [date-range-picker](../../src/components/stories/date-range-picker.stories.tsx) |
| `DateInputPicker` (`date-input-picker.tsx`) | A UTC day from a `Calendar` in a popover. It holds the text a `type="date"` input held (`2027-03-01`, `''` when none), shows the day in the language of the app, and clears with a button. The button takes the `id` and the `aria-*` props a field hands down, so a label names it. A text that is not a day shows as none and stays as it is until a day is picked. The button carries the value it holds in `data-value`: the unit, story and E2E helpers read a picker through it (the text is localized), so it stays. The calendar opens with the focus on the chosen day, or on today. Where a form wants the instant, `dateInputToInstant` of `lib/date-input.ts` reads the text as midnight UTC. | [date-input-picker](../../src/components/stories/date-input-picker.stories.tsx) |
| `DateTimePicker` (`date-time-picker.tsx`) | A UTC date and time, as two controls on one row: a date button that opens the `Calendar` (it holds only the calendar and its clear button, and closes with the day picked), and a `TimeField` beside it. It holds the text a `datetime-local` input held (`2027-03-03T10:00`, no zone, no seconds, `''` when none). Picking a day keeps the time already set, or starts at `00:00`. The button shows the day only (`Mar 3, 2027`); the time is in the field, on a 24-hour clock whatever the language of the browser. The pair is a group named by the label of the form field (`groupLabelledBy`, which `DateTimeField` fills with the id of its label), the date button keeps the name the label gives it and reads the day after it as its description, and the time field is named "Time (UTC)". On a row too narrow for both (the two columns of a form, a dialog, a phone) the time field wraps under the button instead of overflowing. A time is taken once both of its segments are filled: while one is empty the value is left as it was, and when the field is left (or Enter is pressed) the form is given the half-filled time with the day, `2027-03-03T10:--`, which its schema refuses; the field then shows it, marked invalid with "Enter a complete time", and nothing replaces it behind the person's back. A field emptied and left goes back to the time the value holds. A time typed before any day is chosen goes on the day picked next, as it is. A text a form hands in that is not a moment shows as it is on the button, marked invalid, and stays until the person picks one; a day with a time that is none shows the day and the time as they are, the time marked invalid. The moment is UTC and the clock of the person is usually not, so while the zone of the browser is not UTC the picker also words the moment on that clock, `= 18:21 in Paris (CEST)` (`= Oct 19, 01:30 in Tokyo (GMT+9)` when the day there is not the UTC day), in the language of the app and on the same 24-hour clock: in one line under the pair, which is the description of the time field (so the time field's label reads "Time (UTC), your local time is shown below"). The line keeps its height while it is empty (the time is half filled, or no moment is chosen), and is announced politely (`aria-live`) as the time changes it. Nothing shows when the browser is in UTC, in a zone that sits at offset zero all year (`Atlantic/Reykjavik`), or at a moment where its clock equals the UTC one (London in winter), and nothing changes in what the picker holds or gives back, which stays the UTC text. `localTimeZone` sets the zone to show it in instead of the browser's, for a story or a test. The day pickers (`DateInputPicker`) show no local time: a UTC day is a day, not a moment. The date button carries the value the pair holds in `data-value`, as `DateInputPicker` does. The calendar offers the years 2000 to 2100, and more when the value lies outside them. `onBlur` runs once the focus has left the pair altogether (the button, the time field and the popups they open count as one), after a half-filled time was settled, which is when a form marks the field as touched. | [date-time-picker](../../src/components/stories/date-time-picker.stories.tsx) |
| `TimeField` (`time-field.tsx`) | A time of day on the 24-hour clock, `HH : mm`, in the look of the other inputs (height, border, radius, focus ring) with a clock button at its end. Each segment is a spin button (`role="spinbutton"`, `aria-valuenow`, `aria-valuemin`, `aria-valuemax`, `aria-valuetext`, named "Hours" and "Minutes"): Up and Down step it and wrap (23 to 00, no carry into the other segment), Page Up and Page Down step by six hours or ten minutes, Home and End go to the first and last value, digits fill it and move on when no other digit could follow (`1` waits for a second digit, `16` and `3` move on; `2` then `5` is `02` then `05`), Backspace empties it, `:` and Right go to the minutes, Left back to the hours. An empty segment shows `--`; the text of a time is `09:30`, `09:--` or `--:30`, and a segment out of range (`25`) is shown as it is, marked invalid. The clock button, or Alt+Down on a segment, opens a popover of two scrollable columns, the hours 00 to 23 and the minutes 00 to 59, with a chevron above and below each that move by one, the chosen value centred and filled with the primary colour, the focused column outlined and a colon between them. Each column is a listbox of options (`aria-selected`) whose selection follows the focus: Up and Down move to the value above and below, Home, End and the Page keys jump, Left and Right change column, a click or a chevron selects, and the field changes at once; Enter and Escape close the popover and return the focus to the segment. `onSettle` runs once the focus has left the field and its popover, or on Enter (which is not prevented, so a form is sent with what the field holds), to settle a time that is half filled. The group takes `aria-label` or `aria-labelledby`, `aria-describedby` and `aria-invalid` (put on the segments). The time is a text, so a form keeps the same one wherever the field sits: `splitTimeText`, `joinTimeText` and the other rules are in `lib/time-field-model.ts`. | [time-field](../../src/components/stories/time-field.stories.tsx) |

## Adding a field

Build it on `FormField` and `useField`, then register it in `fieldComponents` of `app/src/hooks/form.ts`, next to the others, which are imported statically (`JsonField` alone is loaded on demand: see [forms](../03-patterns/forms.md#building-blocks)). Reuse the existing fields before you add one.
